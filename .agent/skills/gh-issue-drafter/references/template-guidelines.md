# Drafting Principles for GitHub Issues

A good feature draft should provide enough detail for a developer to start implementation without being as exhaustive as a full design document.

## Key Sections

### 1. Overview
Focus on the "Why". What problem are we solving? What is the core value proposition? Keep it to 2-3 sentences.

### 2. Requirements
List functional requirements that define "Done". Use checkboxes for easy tracking.

### 3. Proposed Changes
Break down the implementation into logical components. This helps in understanding the scope and identifying potential bottlenecks.

### 4. Impact
Consider both the positive (user value) and the negative/risky (system complexity, breaking changes).

## Tone and Style
- Be direct and technical.
- Use active voice.
- Avoid marketing fluff.
